# WP23 provenance and acceptance boundaries

Audience: independent reviewer and the operator studying the general builder.

The Publication journey is authored through the visible Studio controls from a blank project and empty inspected SQLite database. Its source reuses parameterized visible-control helpers from WP22, never the Equipment JSON fixture as setup. The four tables, columns, composite key, unique constraint, relationships, forms, query AST, navigation, security, identities, source declaration and edits are UI-created. Runtime rows are created only through the generated application's normal New record and Save controls. Separate read-only SQLite handles verify tuple-scoped persistence and exact totals.

The retained Equipment study is opened through its existing private owner configuration and root registration. Additional owner-approved roots locate the separate Publication definition/database/output. No Equipment source/data is copied. Business rows are compared before and after. Adding the test user changes only the project-specific identity store through visible protected provisioning.

The contract corpus is separate scratch data. Both independent owners start empty. One runs every operation cold through a real SDK MCP stdio client forwarding to owner HTTP, the other runs every operation cold over the same HTTP command transport used by Studio, using the actual owner-session cookie, origin and CSRF protocol. Opposite-transport matching replay is an additional assertion, never the evidence for cold writes. Scratch schema is authored through public commands. No test directly calls core state mutation, seeds SQL, or injects jobs. Read-only SQLite inspects the actual migration result; authored source bytes and generated output files are checked independently.

The discovered operation inventory is asserted against executed operations. Each corpus includes project create/list/open/inspect/batch/validate/export; connection inspect/bind; schema preview/apply/history/restorePreview/restoreApply; query preview; form construction and page/form/control/policy/extension batch mutations; identity configure/provision; source read and extension read/write; generation preview/apply; flow application/endpoint inspection; runtime context/route/status/build/run/stop; and real job inspection/cancellation. Schema flow projection is explicitly unsupported by this operation and is not claimed.

Cold outcomes, revisions and diagnostics are compared across independent corpora after normalizing opaque service UUIDs and external database fingerprints. Known IDs, entity values, references and revision counts remain. Build polling repeats are deduplicated for comparison because process timing varies. Matching request replay is compared exactly, including plan/result hashes and IDs. Final project snapshots are compared independently. Plan IDs/hashes/timestamps are not compared across roots: they intentionally incorporate private path identity and ephemeral review state.

Negative corpus cases retain a byte-equivalent committed snapshot: duplicate-route batch (including unrelated would-be partial page), invalid AST, stale revision, duplicate request with conflicting input, stale extension hash, and missing exact required generation acknowledgement. The same-key matching replay returns its original outcome. Runtime.route before a running tree reports PROJECT_BUSY; after real build/run it resolves and the actual HTTP page succeeds.

Tracing is off because browser traces record masked password fill arguments. Retained browser logs contain operation names and statuses only. Owner/MCP configuration files remain private with mode 0600; visitor passwords are ephemeral and omitted from artifacts.

## Reviewed generic fidelity correction

The visible second-domain journey exposed bound table links displaying a caption instead of the row value. A separate read-only compile/emission probe confirmed ordinary Record captions were ignored and a `change` binding compiled without execution or diagnostics. Both mismatches were reported before production edits; the coordinator authorized the bounded corrections.

Supported bindings now follow actual target behavior: Record button click/submit to insert/update/delete/cancel/extension; Login button click/submit to login/logout, with click Cancel navigation; Grid/Search click links to navigate; one table Grid/Search button click/submit to search. Native GET filtering uses that single declared Search caption and the existing declared-action access guard. Multiple Search bindings, input change/click handlers, link submit, and incompatible action/control combinations fail before emission with the source control ID and recovery instructions. No client event runtime was added. Forms without declared Search bindings retain the built-in filter button.

The fresh-only Record constructor supplies Save/Delete/Cancel defaults. Existing explicit captions remain authoritative, including arbitrary escaped characters and empty strings; operation IDs and authorization do not derive from text. Bound Grid/report links use the same formatter/null handling as other displayed values, while unbound action links retain captions. The report-specific string-replacement workaround was removed in favor of the shared value emitter.
