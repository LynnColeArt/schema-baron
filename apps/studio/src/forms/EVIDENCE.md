# WP11 — focused forms and ordinary editing

The public `form.construct` operation now materializes ordinary page/form/control/action objects, including a linked Grid/Record, through the same `applyBatch` whole-candidate validation path as `project.batch`. A successful construction increments the semantic revision exactly once. Invalid source/field/Record-key choices commit nothing. UI and MCP call the registered operation; there is no wizard-only model or alternate store.

The five bounded steps cover source, field selection, ordered keys, action/destination choices, search/sort and appearance. Finish selects the form and closes the dialog. Required unsaved parent-page objects may join the atomic construction; existing unrelated page names, controls and action drafts remain local. Cancel/Escape restore launcher focus, and closing is disabled while Finish is awaiting its observed outcome. Login asks for no credentials and constructs ordinary declarations only.

Contextual Format/Data/Events edit the same canonical objects. Field controls cover labels, text, numbers, dates, booleans, lookup/select, links and buttons. Derived/query bindings remain read-only; incompatible committed bindings produce object/field diagnostics. The allowed event declarations remain `click`/`change`/`submit`; declared `Action.extensionHookRef` values select source contracts. No before/after/load execution phase is claimed or invented; WP21 owns that later runtime phase contract. Defaults remain authoritative column expressions and are displayed with their type/nullability, rather than adding a second default-evaluation mechanism. Record writes and authentication execution remain WP12/WP13 work.

## Shared integration rationale

- `packages/model/src/commands.ts`: extend the existing strict operation with optional typed search/sorting/action definitions, linked Record choices and bounded pending ordinary authoring operations; legacy actions/links remain supported.
- `packages/core/src/project/index.ts`: register the existing operation and extract the existing non-persisting batch staging helper so pending parent objects and construction receive one final validation/revision.
- `apps/studio/src/workspace/index.tsx`: replace the blank-form shortcut, expose all control commands, delegate form/control Properties, select owning forms for action diagnostics, include action drafts in document discard, and keep input editable while Save awaits the owner.
- Two native-zoom keyboard scroll regions (`modebar` and an empty `message-table`) now have labelled focusable containers; the existing shared `[tabindex]:focus-visible` rule supplies their focus indicator. Cached axe identified the exact two failures; no layout changes were needed.
- Workspace state/recovery: support action drafts and construction undo/redo, acknowledge only submitted Save values, preserve later typing/focus/caret and use bounded editing schemas separate from strict committed schemas. Incomplete lookup tuples, function arguments, references and finite scalar settings survive recovery/history. Separate bounded raw scalar buffers retain `-`, `1e`, empty required values and invalid ranges without NaN/null coercion. They survive object/project switches and reload, display localized errors, block global Save, and only block Wizard Finish when required by its pending parent subtree. Completed numeric buffers defer to changed model values after remote edits or model undo/redo.
- Existing workspace browser proof: replace its obsolete blank Login shortcut with the real wizard; assert Finish's single revision and the separate subsequent Save revision, plus unrelated pending control preservation. Dirty close/reopen, stable IDs, MCP conflicts, undo/redo and invalid Save checks remain.
